# 🧾 pg-accountant — ربات حسابداری حجم ادمین‌های پنل PasarGuard

ربات تلگرامی که هر روز به‌ت میگه **هر ادمین دقیقاً چقدر حجم ساخته**، با اسم یوزرها.
هدفش اینه که دیگه حساب‌کتاب با ادمین‌ها رو به عهده‌ی خودشون نذاری.

> 🔒 این بات فقط از دیتابیس پنل **می‌خواند**. هیچ رکوردی در پنل ایجاد، ویرایش یا
> حذف نمی‌کند. دفتر حساب خودش را در یک فایل SQLite جدا (`ledger.db`) نگه می‌دارد.

---

## چرا این بات لازم است؟

پنل پاسارگارد «حجم مصرفی هر ادمین» را نشان می‌دهد، ولی آن عدد **مصرف واقعی** است —
یعنی هر بار که یک یوزر ریست می‌شود یا اکانتی حذف می‌شود، آن عدد دیگر با چیزی که
ادمین واقعاً «فروخته» برابر نیست. این بات **حجم ساخته‌شده** را حساب می‌کند:

| کاری که ادمین می‌کند | در گزارش پنل | در این بات |
|---|---|---|
| اکانت ۱۰۰ گیگ می‌سازد، مشتری مصرف نمی‌کند | ۰ | **۱۰۰ گیگ** |
| اکانت ۳۰ گیگ می‌سازد و چند ساعت بعد حذف می‌کند | ۰ (ناپدید می‌شود) | **۳۰ گیگ** |
| اکانت ۱۰ گیگ، تا ۹٫۹ گیگ مصرف، بعد حذف | ~۹٫۹ گیگ | **۱۰ گیگ** |
| اکانت ۴۰ گیگ، ۳۹ گیگ مصرف، بعد **ریست** | ۳۹ گیگ (و بعد ۰) | **۸۰ گیگ** (۴۰ + ۴۰) |
| حجم اکانت موجود را از ۱۰۰ به ۱۶۰ زیاد می‌کند | تغییری نیست | **+۶۰ گیگ** |
| ریست دسته‌جمعی همه‌ی یوزرهایش | لاگی نمی‌ماند | **شناسایی می‌شود** ✅ |

## 🔧 نصب (۵ دقیقه)

### ۱) فایل‌ها را روی سرور پنل بگذارید

```bash
# روی سرور پنل
cd /opt
git clone https://github.com/your-repo/pg-accountant.git   # یا scp کنید
cd pg-accountant
```

اگر گیت ندارید، با `scp` از کامپیوتر خودتان:

```bash
scp -r pg-accountant root@YOUR_SERVER:/opt/
```

### ۲) توکن بات را از BotFather بگیرید

در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید:

```
/newbot
```
یک اسم و یک یوزرنیم بدهید (یوزرنیم باید به `bot` ختم شود). توکن را کپی کنید —
چیزی شبیه `7123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.

### ۳) آیدی چت خودتان را بگیرید

به [@userinfobot](https://t.me/userinfobot) پیام بدهید تا آیدی عددی‌تان را بدهد.
برای گروه: بات را در گروه ادمین کنید و آیدی گروه (که با `-100` شروع می‌شود) را بگیرید.

### ۴) نصب خودکار

```bash
cd /opt/pg-accountant
sudo bash install.sh --token "7123456789:AAHxxxx" --chats "123456789,-1001234567890"
```

یا بدون آرگومان تا تعاملی بپرسد:

```bash
sudo bash install.sh
```

اسکریپت نصب خودش:
- نوع دیتابیس پنل را از `/opt/pasarguard/.env` تشخیص می‌دهد
- درایور مناسب (`psycopg2-binary` / `pymysql` / sqlite) را نصب می‌کند
- سرویس `systemd` می‌سازد و فعال می‌کند
- اتصال به دیتابیس را تست می‌کند

### ۵) بررسی کنید که کار می‌کند

```bash
sudo systemctl status pg-accountant
sudo tail -f /var/log/pg-accountant.log
```

در تلگرام به بات `/today` بفرستید.

## 📱 دستورهای بات

| دستور | کار |
|---|---|
| `/today` یا `/status` | وضعیت امروز + آخرین اسکن |
| `/report` | گزارش روزانه (پیش‌فرض: دیروز) |
| `/report 2026-09-20` | گزارش یک روز خاص |
| `/week` یا `/week 14` | جمع ۷ یا ۱۴ روز اخیر |
| `/admin ali` | جزئیات امروزِ یک ادمین |
| `/admins` | فهرست ادمین‌های پنل |
| `/user test1` | تاریخچه‌ی کامل یک اکانت |
| `/scan` | اسکن فوری دیتابیس |
| `/help` | راهنما |

## ⚙️ تنظیمات

فایل `/opt/pg-accountant/config.ini`:

```ini
[bot]
bot_token = ...                  ; توکن BotFather
allowed_chat_ids = 123,-100456   ; فقط این چت‌ها اجازه دارند

panel_env_file = /opt/pasarguard/.env   ; آدرس دیتابیس از اینجا خوانده می‌شود
panel_db_url =                          ; یا دستی واردش کنید (اولویت با این)

timezone = Asia/Tehran
report_time = 00:00              ; ساعت ارسال گزارش روزانه
report_previous_day = true       ; گزارشِ دیروز (true) یا امروز (false)
scan_interval = 60               ; فاصله‌ی اسکن به ثانیه

reset_drop_tolerance = 1048576   ; افت مصرف کمتر از ۱ مگ = ریست حساب نمی‌شود
count_topup = true               ; افزایش حجم اکانت موجود بیل شود
backfill_on_first_run = true     ; اکانت‌های موجود در اولین اجرا ثبت شوند
backfill_days = 30               ; فقط اکانت‌های ۳۰ روز اخیر
```

### نکته‌ی مهم درباره‌ی اولین اجرا

در اولین اجرا، بات **اکانت‌های موجود در پنل را هم ثبت می‌کند** (backfill) تا
آمار از همان روز اول کامل باشد. اگر نمی‌خواهید گذشته در آمار بیاید، **قبل از
اولین اجرا** این را بگذارید:

```ini
backfill_on_first_run = false
```

## 🛠 استفاده از خط فرمان

```bash
BIN=/opt/pg-accountant/venv/bin/python
BOT=/opt/pg-accountant/bot.py
CFG=/opt/pg-accountant/config.ini

sudo $BIN $BOT -c $CFG health      # تست اتصال به دیتابیس پنل
sudo $BIN $BOT -c $CFG scan        # یک اسکن فوری
sudo $BIN $BOT -c $CFG status      # وضعیت
sudo $BIN $BOT -c $CFG report      # گزارش دیروز (چاپ در ترمینال)
sudo $BIN $BOT -c $CFG report 2026-09-20 --send   # ارسال به تلگرام
sudo $BIN $BOT -c $CFG daily       # گزارش دیروز + ارسال (برای cron)
```

### اجرا با cron به‌جای گزارش داخلی

اگر ترجیح می‌دهید گزارش را cron بفرستد (مثلاً چون بات را با
`run --no-telegram` اجرا می‌کنید):

```bash
sudo crontab -e
# هر روز ساعت ۰۰:۰۵ به وقت سرور:
5 0 * * * /opt/pg-accountant/venv/bin/python /opt/pg-accountant/bot.py -c /opt/pg-accountant/config.ini daily >> /var/log/pg-accountant.log 2>&1
```

## ❓ سؤال‌های رایج

**اگر بات خاموش شود چه؟**
اکانت‌هایی که در فاصله‌ی خاموشی ساخته شده و هنوز **موجود** باشند، از روی
`users.created_at` بازیابی می‌شوند. اما اکانتی که در آن فاصله **ساخته و حذف** شده
باشد قابل بازیابی نیست (چون پنل اثری از آن نگه نمی‌دارد). اگر بات بیش از
۵ دقیقه خاموش بوده باشد، در گزارش هشدار می‌گیرد.

**چقدر دقیق است؟**
به `scan_interval` بستگی دارد. با ۶۰ ثانیه، تنها حالتی که از دست می‌رود این است
که ادمین اکانتی را **در کمتر از ۶۰ ثانیه** بسازد و حذف کند. برای دقت بیشتر
`scan_interval = 15` بگذارید (بار روی دیتابیس ناچیز است).

**آیا روی سرعت پنل اثر می‌گذارد؟**
نه. هر اسکن دو کوئری `SELECT` ساده است (`users` و `admins`) و با فاصله‌ی ۶۰
ثانیه. روی دیتابیس ۱۰ هزار کاربری هم میلی‌ثانیه‌ای است.

**رمز دیتابیس کجاست؟**
در `config.ini` ذخیره نمی‌شود؛ بات هر بار از `/opt/pasarguard/.env` می‌خواند.
خودِ `config.ini` هم با دسترسی `۶۰۰` است.

**می‌شود بات را روی سرور دیگری نصب کرد؟**
بله، به‌شرطی که به دیتابیس پنل دسترسی شبکه داشته باشد. در این حالت
`panel_db_url` را دستی و با IP واقعی پر کنید و در فایروال، پورت دیتابیس را فقط
برای IP بات باز کنید.

## 🔩 چطور کار می‌کند؟

هر `scan_interval` ثانیه، بات جدول `users` پنل را می‌خواند و با دفترکل خودش
مقایسه می‌کند:

- **کاربر جدید** → رویداد `provision` با حجم `data_limit`
- **مصرف افت کرده** (`used_traffic` کم شده) → رویداد `reset` با حجم پلن
- **حجم زیاد شده** → رویداد `topup` با مابه‌التفاوت
- **حجم و مصرف هم‌زمان عوض شده** (مثل `next_plan`) → رویداد `renewal`، یک بار
- **کاربر ناپدید شده** → رویداد `deleted` (بدون بار مالی، چون قبلاً حساب شده)

`data_limit` پنل به **بایت** است؛ بات همان را بیل می‌کند و در گزارش به
گیگ/ترابایت (مبنای ۱۰۲۴، مثل خود پنل) نشان می‌دهد.
